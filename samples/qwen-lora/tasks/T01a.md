# Task T01a: the T01 documents (no code)

T01 is the unit `GgufFile` (GGUF reader) and the program `qlora_inspect`,
split into T01a (documents), T01b1 and T01b2 (the unit and its UT) and
T01c (the program, its UT and the ITa run). This is T01a.

Read `{proj}/tasks/T01-facts.md` first: it fixes the format, the interface,
the command line, the output and the oracle. The documents only restate
and organise it; do not change any decision in it and do not read DESIGN.md
(the facts were taken from it).

Main agent (you):
1. Write `{proj}/docs/external-design/T01-external.md` (purpose, command
   line, output, exit codes, errors; from the facts) and
   `{proj}/docs/system-flow/T01-system.md` (the program: arguments →
   `RunInspectCLI` → `TGgufFile.Open` → output lines → exit code).
2. Write the ITa cases as a table in `{proj}/tests/ita/cases/T01-ita.cases.md`:
   columns `| Case ID | Title | Expected (short) |`, IDs `ITa-T01-001`...
   One case per comparison of the facts' oracle section (summary lines,
   `kv` lines, `tensor` lines, the `llama-server` per-type counts), plus:
   exit code 0 on the model; a file that is not GGUF (exit 1, nothing on
   stdout); a copy of the model cut short by one byte (exit 1, nothing on stdout:
   `Open` fails); a copy with one byte appended (exit 1, all lines, then
   the "data ends" message); no argument (exit 2); the model given by a relative path from
   another working directory. Each case says the exact command.
3. Delegate one task to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`): write `{proj}/docs/detailed-design/T01-detailed.md`
   (one section per routine of the facts' interface and of `RunInspectCLI`,
   with its checks and errors in the order the facts give them) and
   `{proj}/docs/program-flow/T01-GgufFile-flow.md`.
4. Delegate one task to the sub-agent (skill `sdlc-ut-tdd`): write the UT
   case tables `{proj}/tests/ut/cases/GgufFile.cases.md` (IDs
   `UT-GgufFile-NNN`) and `{proj}/tests/ut/cases/InspectCli.cases.md`
   (IDs `UT-InspectCli-NNN`), covering every item of the facts' "Unit
   tests" list and every error of the detailed design. No source code in
   this task.

Write each file in pieces of at most about 150 lines (`patch` or several
`write_file` calls), never a whole long file in one reply.

Report at the end: files written, the number of rows in each case table.
