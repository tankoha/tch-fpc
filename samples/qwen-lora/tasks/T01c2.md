# Task T01c2: fix BUG-005 (`GgufFile` error messages after `Destroy`)

Read `{proj}/docs/defects.md`, row BUG-005. T01 is otherwise done; change
nothing but what this task names.

The defect: in `{proj}/src/GgufFile.pas`, `TGgufFile.Open` calls `Destroy;`
before each `raise EGgufError...`. `Destroy` sets `FFileSize` and
`FDataOffset` to 0 before the message arguments are evaluated, so a model
cut short by one byte says "but the file is 0 bytes".

Fact (FPC, final): when a constructor raises, FPC calls `Destroy` itself and
frees the instance. The explicit `Destroy;` calls before the raises are
therefore not needed and are to be removed (all 11 of them in `Open` and the
routines it calls; `search_files` for `Destroy;` in that file). `Destroy`
itself stays as it is (it must work on a half-built object: `FStream` may be
nil).

Main agent (you): delegate one task to the sub-agent (skill `sdlc-ut-tdd`):
1. First add one UT case row `UT-GgufFile-049` to
   `{proj}/tests/ut/cases/GgufFile.cases.md`: a file whose last tensor ends
   one byte past the end of the file; the `EGgufError` message contains the
   tensor's name and the real file size (`IntToStr` of the file's size).
   Add its test method to `{proj}/tests/ut/GgufFile_test.pas` (find the
   test of UT-GgufFile-039 with `search_files` and copy its set-up). Run it
   and see it fail.
2. Remove the explicit `Destroy;` calls; run the test again and see it
   pass.
3. Run `~/.hermes/agent-hooks/sdlc.bb gate ut {proj} --run` (it must be OK,
   with coverage 100 %) and append the result rows to
