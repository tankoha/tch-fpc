# Task T09a: the T09 documents (no code)

T09 adds `DeltaRuleChunked` to the unit `DeltaRule` (T08): the gated delta
rule in the chunked form, checked against T08's `DeltaRuleTokens`. It is
split into T09a (documents), T09b1 and T09b2 (the function and its UT, one
stage each) and T09c (the ITa run). This is T09a. It uses **2
delegations**.

Read `{proj}/tasks/T09-facts.md` first: it fixes the chunked form, the
interface, the implementation, the messages, the UT rows, the ITa and the
case-ID ranges. The documents only restate and organise it. Do not read
DESIGN.md, other task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T09-external.md` (purpose, the
   chunked form, the interface and its errors, "G must be finite", as in
   the facts) and `{proj}/docs/system-flow/T09-system.md` (callers: T10's
   linear block uses it for training and scoring; the UT and the ITa
   compare it with `DeltaRuleTokens` (T08) and with the fixture's scalar
   reference `RefTokens`; the ITa driver `tests/ita/T09/chunked_check.pas`
   runs it at the 27B model's sizes).
2. Write `{proj}/tests/ita/cases/T09-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T09-001 to 006 as in
   the facts (the expected column gives the limit), and under the table
   the command `<project root>/tests/ita/T09-run.sh` (no variable is
   needed) and its result file `<project root>/work/ita/T09/summary.tsv`
   (write `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`): write
   `{proj}/docs/detailed-design/T09-detailed.md` (one section for the
   padding, one for the per-chunk matrices (Decay, L, Tm, U, W), one for
   the loop over the chunks and the final state, one for the checks with
   every message in order; each with the tensor-op sequence of the facts)
   and `{proj}/docs/program-flow/T09-DeltaRuleChunked-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`): **add** the
   rows of the facts' "Unit tests" tables (IDs `UT-DeltaRule-201` to `224`,
   24 rows) at the end of the existing UT case table
   `{proj}/tests/ut/cases/DeltaRule.cases.md` with `patch` (same columns;
   the target function `DeltaRuleChunked`), the inputs and expected values
   copied from the facts. Do not change its existing rows. No source code.
   Then run the review again and count the rows with
   `grep -c '^| UT-DeltaRule-2' {proj}/tests/ut/cases/DeltaRule.cases.md`.

Report at the end: the `ls -l` of every file written, the row count of the
new rows, the review's output.
