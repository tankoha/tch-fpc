# Task T10a: the T10 documents (no code)

T10 is two units: `PackedLinear` (a GGUF matrix kept packed on a device,
dequantised per call) and `QwenBlocks` (RMS norm, RoPE, the FFN, the
linear and the full trunk block of `qwen35`, as `Recompute` stages). It is
split into T10a (documents), T10b1 to T10b4 (the units and their UT, one
stage each) and T10c (the ITa run). This is T10a. It uses **2
delegations**.

Read `{proj}/tasks/T10-facts.md` first: it fixes the interfaces, the
implementation, the messages, the UT rows, the ITa and the case-ID ranges.
The documents only restate and organise it. Do not read DESIGN.md, other
task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T10-external.md` (purpose of both
   units, the block skeleton, the linear and the full block step by step,
   the interfaces and their errors, as in the facts) and
   `{proj}/docs/system-flow/T10-system.md` (callers: T11's model runs the
   trunk as stages with T13's `Recompute`; T12 adds LoRA to
   `TPackedLinear`; the UT compares with the slow scalar version
   `tests/ut/QwenRefScalar.pas` on the tiny model of
   `tests/ut/QwenBlocksFixture.pas`; the ITa driver
   `tests/ita/T10/blocks_check.pas` runs every block of the rehearsal
   model against the scalar version).
2. Write `{proj}/tests/ita/cases/T10-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T10-001 to 005 as in
   the facts (the expected column gives the limit), and under the table
   the command `QLORA_MODEL=<rehearsal GGUF> <project root>/tests/ita/T10-run.sh`
   and its result file `<project root>/work/ita/T10/summary.tsv` (write
   `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`): write
   `{proj}/docs/detailed-design/T10-detailed.md` (sections: `PackedLinear`;
   the helpers `ReadQwenDims`, `RmsNorm`, `RopeText`; `TQwenBlock`;
   `TFullBlock`; `TLinearBlock`; the checks with every message in order;
   each with the tensor-op sequence of the facts) and
   `{proj}/docs/program-flow/T10-QwenBlocks-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`): write the UT
   case tables `{proj}/tests/ut/cases/PackedLinear.cases.md` (rows
   `UT-PackedLinear-001` to `015`, 15 rows) and
   `{proj}/tests/ut/cases/QwenBlocks.cases.md` (rows `UT-QwenBlocks-101` to
   `107`, `201` to `204`, `211` to `215`, 16 rows) with exactly the rows of
   the facts' "Unit tests" tables (columns as in
   `{proj}/tests/ut/cases/GgufWriter.cases.md`), the inputs and expected
   values copied from the facts. No source code. Then run the review again
   and count the rows with `grep -c '^| UT-' <file>` for each file.

Report at the end: the `ls -l` of every file written, the row counts, the
review's output.
