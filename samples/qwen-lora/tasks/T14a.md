# Task T14a: the T14 documents (no code)

T14 is the unit `LoraOptim` (the sample's own AdamW: moments in a second
`TVarStore` per parameter store so they can be saved, global-norm clipping
over several stores, the learning-rate schedule), split into T14a
(documents), T14b1, T14b2 and T14b3 (the unit and its UT, one stage each)
and T14c (the ITa run). This is T14a. It uses **2 delegations**.

Read `{proj}/tasks/T14-facts.md` first: it fixes the interface, the
implementation, the messages, the UT rows, the ITa and the case-ID
ranges. The documents only restate and organise it. Do not read DESIGN.md,
other task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T14-external.md` (purpose, the
   update rule, the schedule, the interface and its errors, as in the
   facts) and `{proj}/docs/system-flow/T14-system.md` (callers: T17's
   training step clips and updates the LoRA stores of both GPUs every
   second batch; T16's checkpoint saves the moment stores and
   `StepCount`; the UT compares with hand values and with the fixture's
   `ReferenceRun` (libtorch's `TOptimizer.AdamW`); the ITa driver
   `tests/ita/T14/loraoptim_check.pas` runs the toy problem on the CPU).
2. Write `{proj}/tests/ita/cases/T14-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T14-001 to 007 as in
   the facts (the expected column gives the limit), and under the table
   the command `<project root>/tests/ita/T14-run.sh` (no variable is
   needed) and its result file `<project root>/work/ita/T14/summary.tsv`
   (write `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`): write
   `{proj}/docs/detailed-design/T14-detailed.md` (one section each for
   `DefaultAdamWConfig` and `ScheduleLR`, for `Create` / `Destroy` /
   `ZeroGrad` / `StoreCount` / `Moments`, for `ClipGlobalNorm`, for
   `Step`, and one for the checks with every message in order; each with
   the steps of the facts' "Implementation") and
   `{proj}/docs/program-flow/T14-LoraOptim-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`): write the UT
   case table `{proj}/tests/ut/cases/LoraOptim.cases.md` with exactly the
   rows of the facts' "Unit tests" tables (IDs `UT-LoraOptim-001` to `016`
   and `101` to `112`, 28 rows; columns as in
   `{proj}/tests/ut/cases/GgufWriter.cases.md`), the inputs and expected
   values copied from the facts. No source code. Then run the review again
   and check the file with `ls -l` and count its rows with
   `grep -c '^| UT-LoraOptim-' {proj}/tests/ut/cases/LoraOptim.cases.md`.

Report at the end: the `ls -l` of every file written, the row count of the
case table, the review's output.
