# Task T15a: the T15 documents (no code)

T15 is the unit `TrainData` (the data set file becomes training samples,
an epoch becomes batches within a position budget, a batch becomes
tensors with the loss mask). It is split into T15a (documents), T15b1 and
T15b2 (the code and its UT, one stage each) and T15c (the ITa run). This
is T15a. It uses **2 delegations**. **No source code and no tests are
written in T15a**: not by you, not by the sub-agent.

Read `{proj}/tasks/T15-facts.md` first: it fixes the interface, the
implementation, the messages, the UT rows, the ITa and the case-ID ranges.
The documents only restate and organise it. Do not read DESIGN.md, other
task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T15-external.md` (purpose of the
   unit, the record keys, the admission by class and length, the
   rendering without thinking and the loss span, why there is no token
   cache, the epoch order, the pools and the budget, resuming by skipping
   batches, the three tensors, the errors, as in the facts) and
   `{proj}/docs/system-flow/T15-system.md` (callers: T17's training loads
   the set, takes the batches of each epoch, skips those of a resumed
   checkpoint's position (T16) and builds the tensors; T19's
   `qlora_dataset` writes the records with their class; the open question
   of the facts on one sequence per forward; the UT on T05's tiny
   tokenizer; the ITa driver `tests/ita/T15/data_check.pas` on the
   rehearsal tokenizer, three processes).
2. Write `{proj}/tests/ita/cases/T15-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T15-001 to 005 as in
   the facts (the expected column gives the limit), and under the table
   the command `QLORA_MODEL=<rehearsal GGUF> <project root>/tests/ita/T15-run.sh`
   and its result file `<project root>/work/ita/T15/summary.tsv` (write
   `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`). Put this sentence into the goal
   itself: "Write only the two documents named here; no source code, no
   tests, no case tables; stop when both files exist." The documents:
   `{proj}/docs/detailed-design/T15-detailed.md` (sections: the types;
   `SplitMix64`, `StateOf`, `Shuffle`; `EncodeSample`; `HasWideEscape`,
   `GetStr`; `TTrainSet` (`Create`, `Count`, `MaxLength`, `GetSample`);
   `EpochOrder`; `EpochBatches`; `SkipBatches`; `BatchTensors`; the
   checks with every message in order) and
   `{proj}/docs/program-flow/T15-TrainData-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`). Put this
   sentence into the goal itself: "Write only the case table named here;
   no source code, no tests; do not run the gate; stop when the table is
   written." The table, with exactly the rows of the facts' "Unit tests"
   tables (columns as in `{proj}/tests/ut/cases/GgufWriter.cases.md`), the
   inputs and expected values copied from the facts:
   `{proj}/tests/ut/cases/TrainData.cases.md` (new): rows
   `UT-TrainData-001` to `014` and `101` to `110`, 24 rows. Then run the
   review again and count the rows with `grep -c '^| UT-' <file>`.

Report at the end: the `ls -l` of every file written, the row count, the
review's output.
