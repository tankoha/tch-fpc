# Task T16a: the T16 documents (no code)

T16 is the unit `Checkpoint` (saving and restoring a LoRA run: the
adapters, the AdamW moments, the run state). It is split into T16a
(documents), T16b1 and T16b2 (the code and its UT, one stage each) and
T16c (the ITa run). This is T16a. It uses **2 delegations**. **No source
code and no tests are written in T16a**: not by you, not by the
sub-agent.

Read `{proj}/tasks/T16-facts.md` first: it fixes the interface, the
implementation, the messages, the UT rows, the ITa and the case-ID ranges.
The documents only restate and organise it. Do not read DESIGN.md, other
task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T16-external.md` (purpose of the
   unit, the layout of a checkpoint directory, the save through a
   temporary directory and a rename, the retention rule, the keys of
   `state.json`, why the moments are stored by variable name, the errors,
   as in the facts) and `{proj}/docs/system-flow/T16-system.md` (callers:
   T17's training saves every 50 updates and at the end of each epoch and
   resumes from `Latest`; T18's `qlora_merge` reads `lora.ot` and the rank
   and scale of `state.json` through `ReadRunState`; the UT on a small set
   without a model; the ITa driver `tests/ita/T16/ckpt_check.pas` on the
   rehearsal model, four processes).
2. Write `{proj}/tests/ita/cases/T16-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T16-001 to 004 as in
   the facts (the expected column gives the limit), and under the table
   the command `QLORA_MODEL=<rehearsal GGUF> <project root>/tests/ita/T16-run.sh`
   and its result file `<project root>/work/ita/T16/summary.tsv` (write
   `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`). Put this sentence into the goal
   itself: "Write only the two documents named here; no source code, no
   tests, no case tables; stop when both files exist." The documents:
   `{proj}/docs/detailed-design/T16-detailed.md` (sections: `TRunState`
   and `NewRunState`; `RunStateToJson` with `CheckAscii`;
   `RunStateFromJson` with `GetInt`, `GetFloat`, `GetStr`; `ReadText`,
   `WriteText`, `ReadRunState`; `CheckOptim`, `MomentsOf`, `SaveMoments`,
   `LoadMoments`; `TCheckpoints` (`Create`, `DirOf`, `RemoveTree`, `List`,
   `Latest`, `Best`, `Prune`, `Save`, `Load`); the checks with every
   message in order) and `{proj}/docs/program-flow/T16-Checkpoint-flow.md`.
   Then run `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with
   `ls -l` that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`). Put this
   sentence into the goal itself: "Write only the case table named here;
   no source code, no tests; do not run the gate; stop when the table is
   written." The table, with exactly the rows of the facts' "Unit tests"
   tables (columns as in `{proj}/tests/ut/cases/GgufWriter.cases.md`), the
   inputs and expected values copied from the facts:
   `{proj}/tests/ut/cases/Checkpoint.cases.md` (new): rows
   `UT-Checkpoint-001` to `012` and `101` to `120`, 32 rows. Then run the
   review again and count the rows with `grep -c '^| UT-' <file>`.

Report at the end: the `ls -l` of every file written, the row count, the
review's output.
