# Task T18a: the T18 documents (no code)

T18 is the D3 writer: the unit `GgufMerge` (the adapted matrices of a base
GGUF, the checkpoint's adapters, one merged tensor, the merged file, the
command line) and the program `src/qlora_merge.pas` (the harness owner's,
complete). It is split into T18a (documents), T18b1 and T18b2 (the code
and its UT, one stage each) and T18c (the ITa run). This is T18a. It uses
**2 delegations**. **No source code and no tests are written in T18a**:
not by you, not by the sub-agent.

Read `{proj}/tasks/T18-facts.md` first: it fixes the interface, the
implementation, the messages, the UT rows, the ITa and the case-ID ranges.
The documents only restate and organise it. Do not read DESIGN.md, other
task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T18-external.md` (purpose of the
   program, the command line with its option, what the merged file holds
   (the metadata as bytes, the tensor order, the adapted matrices in Q8_0,
   the rest byte for byte), the targets, the base's sha256 check, the
   part file, the exit codes, the errors, as in the facts) and
   `{proj}/docs/system-flow/T18-system.md` (what it uses: GgufFile,
   GgufQuant, GgufWriter, QwenBlocks, Lora, Checkpoint, TrainCli; who runs
   it: the harness owner on the rehearsal model (M2, H47), the user on the
   27B (M4, then `ollama create`, H45); its input from T17's checkpoints;
   the UT on the tiny model; the ITa with its two runs, the driver and the
   llama-server reference).
2. Write `{proj}/tests/ita/cases/T18-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T18-001 to 006 as in
   the facts (the expected column gives the limit), and under the table
   the command `QLORA_MODEL=<rehearsal GGUF> <project root>/tests/ita/T18-run.sh`
   and its result file `<project root>/work/ita/T18/summary.tsv` (write
   `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`). Put this sentence into the goal
   itself: "Write only the two documents named here; no source code, no
   tests, no case tables; stop when both files exist." The documents:
   `{proj}/docs/detailed-design/T18-detailed.md` (sections: `MergeTargets`
   with `AddTarget`; `LoadAdapters`; `MergeTensor`; `WriteMerged` step by
   step (pairs by tensor index, retyping, the part file, the rename);
   `RunMergeCLI` step by step; the checks with every message in order) and
   `{proj}/docs/program-flow/T18-qlora_merge-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`). Put this
   sentence into the goal itself: "Write only the case table named here;
   no source code, no tests; do not run the gate; stop when the table is
   written." The table, with exactly the rows of the facts' "Unit tests"
   tables (columns as in `{proj}/tests/ut/cases/GgufWriter.cases.md`), the
   inputs and expected values copied from the facts:
   `{proj}/tests/ut/cases/GgufMerge.cases.md` (new): rows
   `UT-GgufMerge-001` to `014` and `101` to `106`. Then run the review
   again and count the rows with `grep -c '^| UT-' <file>`.

Report at the end: the `ls -l` of every file written, the row count, the
review's output.
