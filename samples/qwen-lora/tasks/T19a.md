# Task T19a: the T19 documents (no code)

T19 is the data set builder `qlora_dataset`: the unit `DatasetFilter` (the
pure parts: schema, fenced blocks, normalised source, tokens, shingles,
Jaccard, the split), the unit `DatasetCli` (the command line and the run)
and the program `src/qlora_dataset.pas` (the harness owner's, complete).
It is split into T19a (documents), T19b1 and T19b2 (the code and its UT,
one unit each) and T19c (the ITa run). This is T19a. It uses
**2 delegations**. **No source code and no tests are written in T19a**:
not by you, not by the sub-agent.

Read `{proj}/tasks/T19-facts.md` first: it fixes the interfaces, the
implementation, the messages, the UT rows, the ITa and the case-ID ranges.
The documents only restate and organise it. Do not read DESIGN.md, other
task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T19-external.md` (purpose of the
   program, the command line with every option and its default, the
   record schema, the order of the checks per record with every reject
   reason, the split, the five output files, the exit codes, the errors,
   as in the facts) and `{proj}/docs/system-flow/T19-system.md` (what it
   uses: DialectVerify, QwenTokenizer, GgufFile; where its input comes
   from: the generator's raw JSONL (M3), the evaluation tasks, the example
   directories, the tokenizer reference made with the bundled llama-server;
   where its output goes: TrainData (T15) reads train/valid by class; the
   UT with the stock fpc and the tiny tokenizer; the ITa with its two runs
   and the driver).
2. Write `{proj}/tests/ita/cases/T19-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T19-001 to 006 as in
   the facts (the expected column gives the limit), and under the table
   the command `QLORA_MODEL=<rehearsal GGUF> <project root>/tests/ita/T19-run.sh`
   and its result file `<project root>/work/ita/T19/summary.tsv` (write
   `<project root>` literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`). Put this sentence into the goal
   itself: "Write only the two documents named here; no source code, no
   tests, no case tables; stop when both files exist." The documents:
   `{proj}/docs/detailed-design/T19-detailed.md` (sections: `DatasetFilter`
   (`InList`, `ParseRecord`, `ExtractBlocks`, `NormalizeSource`,
   `SourceKey`, `LexTokens`, `Fnv1a`, `Shingles`, `Jaccard`, `ValidCount`,
   `SplitKey`); `DatasetCli` (`DefaultDatasetConfig`, `ParseDatasetArgs`,
   `MainBlock`, `UnitNameOf`, `VerifyRecord`, the local helpers,
   `RunDatasetCLI` step by step); the checks with every message in order)
   and `{proj}/docs/program-flow/T19-qlora_dataset-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`). Put this
   sentence into the goal itself: "Write only the case tables named here;
   no source code, no tests; do not run the gate; stop when the tables are
   written." The tables, with exactly the rows of the facts' "Unit tests"
   tables (columns as in `{proj}/tests/ut/cases/GgufWriter.cases.md`), the
   inputs and expected values copied from the facts:
   `{proj}/tests/ut/cases/DatasetFilter.cases.md` (new): rows
   `UT-DatasetFilter-001` to `010`; `{proj}/tests/ut/cases/DatasetCli.cases.md`
   (new): rows `UT-DatasetCli-101` to `109`. Then run the review again and
   count the rows with `grep -c '^| UT-' <file>`.

Report at the end: the `ls -l` of every file written, the row counts, the
review's output.
