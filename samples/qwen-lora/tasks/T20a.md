# Task T20a: the T20 documents (no code)

T20 is the evaluation program `qlora_eval`: the unit `EvalReport` (the
pure parts: counts per column, paired flips, the exact sign test, the
adoption rule, the first fenced block), the unit `EvalCli` (the command
line, the tasks, judging the recorded replies, the report) and the program
`src/qlora_eval.pas` (the harness owner's, complete). It is split into
T20a (documents), T20b1 and T20b2 (the code and its UT, one unit each) and
T20c (the ITa run). This is T20a. It uses **2 delegations**. **No source
code and no tests are written in T20a**: not by you, not by the sub-agent.

Read `{proj}/tasks/T20-facts.md` first: it fixes the interfaces, the
implementation, the messages, the UT rows, the ITa and the case-ID ranges.
The documents only restate and organise it. Do not read DESIGN.md, other
task files or any source under `src/` or `tests/`.

Main agent (you):
1. Write `{proj}/docs/external-design/T20-external.md` (purpose of the
   program, the command line with every option and its default, the task
   and reply formats, how a Pascal reply and a regression reply are
   judged, the columns, the flips and the sign test, the adoption rule,
   the two output files, the exit codes, the errors, as in the facts) and
   `{proj}/docs/system-flow/T20-system.md` (what it uses: DialectVerify;
   where its input comes from: the evaluation tasks (M3) and the replies
   recorded with `ask.bb` through Ollama for the "before" (M3) and "after"
   (M5) evaluations; who reads the report: the user, for the adoption
   decision; the UT with the stock fpc; the ITa with its fixed records,
   two runs and the driver).
2. Write `{proj}/tests/ita/cases/T20-ita.cases.md`: columns
   `| Case ID | Title | Expected (short) |`, cases ITa-T20-001 to 005 as in
   the facts (the expected column gives the limit), and under the table
   the command `<project root>/tests/ita/T20-run.sh` and its result file
   `<project root>/work/ita/T20/summary.tsv` (write `<project root>`
   literally, not the absolute path).
3. Delegate (1 of 2) to the sub-agent (skills `sdlc-detailed-design`,
   `pascal-fpc-objfpc`, `tch-fpc`). Put this sentence into the goal
   itself: "Write only the two documents named here; no source code, no
   tests, no case tables; stop when both files exist." The documents:
   `{proj}/docs/detailed-design/T20-detailed.md` (sections: `EvalReport`
   (`InList`, `InColumn`, `CountOf`, `FlipsOf`, `SignTestP`, `PassRate`,
   `DialectsOf`, `Above`, `Adoption`, `FirstBlock`); `EvalCli`
   (`DefaultEvalConfig`, `ParseEvalArgs`, `Lines`, `LoadTasks`,
   `JudgeReply`, `TaskIndex`, `JudgeFile`, `Cell`, `ReportMode`,
   `RunEvalCLI` step by step); the checks with every message in order) and
   `{proj}/docs/program-flow/T20-qlora_eval-flow.md`. Then run
   `~/.hermes/agent-hooks/sdlc.bb review {proj}`, and check with `ls -l`
   that both files exist before you report them.
4. Delegate (2 of 2) to the sub-agent (skill `sdlc-ut-tdd`). Put this
   sentence into the goal itself: "Write only the case tables named here;
   no source code, no tests; do not run the gate; stop when the tables are
   written." The tables, with exactly the rows of the facts' "Unit tests"
   tables (columns as in `{proj}/tests/ut/cases/GgufWriter.cases.md`), the
   inputs and expected values copied from the facts:
   `{proj}/tests/ut/cases/EvalReport.cases.md` (new): rows
   `UT-EvalReport-001` to `009`; `{proj}/tests/ut/cases/EvalCli.cases.md`
   (new): rows `UT-EvalCli-101` to `107`. Then run the review again and
   count the rows with `grep -c '^| UT-' <file>`.

Report at the end: the `ls -l` of every file written, the row counts, the
review's output.
